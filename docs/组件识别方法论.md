# IFC 组件组合识别方法论

目标：不管业务模块是什么，拿到一个功能后，用同一套办法快速、准确地搞清"页面上有什么、怎么操作、怎么检查"。下面每条都来自真实表单定义或 dev 环境的实际观察，不是推测；没验证过的在最后一节单列。

## 1. 先找表单，再读表单定义
1. 功能 → 表单 ID：测试库 MCP `findFormEntries`/`findMenus`（关键字可用功能号、菜单名）。注意**同一个功能可能有多个入口**（例：企业定存存入，核心系统 home 树 ZJ0086、网银 ebank 树 ZW0004），先确认测哪个。
2. 表单 ID → 中文菜单路径：`findMenuPaths`。路径写进工作区 `config/local/<环境>.yaml` 的 `env_params.forms.<表单ID>.menu`。
3. 表单定义 JSON（`knowledge/forms/<表单ID>.json`）里有：`components`（控件树）、`dataModels`、工具栏按钮。从里面抽出：
   - 字段：`showLabelText`（标签）、`dataSetColID`（对应数据库列）、`type`、`enableNotNullCheck`（必填）、`edit`（可编辑）、下拉的 `maskConfigKey`（用 `getMaskDetail` 取全部选项）。
   - 分区：`FormContentPanel` 的标题（基本信息、到期处理、审批流程…）。
   - 表格：网格 key、列表头、列编辑器码（`editorType`）。
   - 工具栏：按钮标签 + 动作类型（见 §3）。

## 2. 字段类型 → 操作方式
| 组件 type | 怎么填 | 注意 |
|---|---|---|
| FormTextInput / FormTextArea / FormNumberInput | 直接输入 | 只读的（如存款天数）只能读不能填 |
| FormDateField | 输入日期文本 | 格式取自控件 |
| FormComboBox | 点开下拉选项 | 选项来自掩码，业务选项以 `getMaskDetail` 为准 |
| HelpComboBox | 点开弹层选择 | 选项随其他字段联动（如币种、存款类型） |
| AmountComp | 币种 + 金额 | 见 §5 已知坑 |
| InterestRateInput | 输入，失焦补零 | 读值必须在失焦后 |
| PaymentUnit / PaymentAccount / AccountOpenOrgan / CountryArea / Currency | 业务弹层选择 | 已有适配器 |
| 网格单元格 | 按列编辑器码选适配器（3 数字、5 日期、6/21 下拉） | 码 7（字典帮助）、30（自定义表单帮助）暂未支持，会明确阻塞 |

没有适配器的组件类型，运行时会**阻塞并说明**，不会乱填。新增适配器放工作区 `extensions/`；框架没有的动作（如撤回、取回、上传附件）也在那里用 `@action` 补。

## 3. 工具栏按钮 → 动作
按钮按**动作类型**识别，不靠文字猜：
- `GeneralActionSave` 保存、`GeneralActionSubmit` 提交、`GeneralAction1` 新建
- `FormEditAction` 编辑
- `FlowSubmitAction` 同意、`FlowRollbackAction` 退回、`FlowRetakeAction` 取回、`FlowEndAction` 作废、`FlowAssignAction` 加签
- 页面上按钮的 CSS 类为 `<表单ID>-<工具栏key>-<动作key>-show-form`（当前可用）或 `-hidden-form`（当前不可用）。**用它判断单据当前状态下能做什么**。

## 4. 按条件显示的字段
同一个标签在表单里可能出现多次，同一时刻只有一个可见（例：两个"起始日期"）。用 `expect_visible` 检查"选了某类型后哪些字段该出现/消失"。企业定存实测：
- 通知存款：出现"提前通知天数"，没有到期日期、存款天数、应计利息、到期指示。
- 跃息存款：出现"跃息存款利率"分录。
- 到期指示选"本息续存下一个定期"：出现下一定期周期、下一定期到期日、下一定期存款天数。

## 5. 已知坑（均已在 dev 实测，框架已处理，写适配器/场景时注意）
- **联动字段要等**：改金额/周期后，应计利息、存款天数等由服务端重算，读值要等一会儿（`expect_field` 会自动多等最多 6 秒）。
- **币种重选会清空表单**：编辑已保存单据时，对币种选择框重选同一个币种，会清空周期、利率并重置金额。已处理：币种相同则不重选。
- **金额框已有值时直接 fill 无效**：要点进去全选后逐键输入。已处理。
- **编辑进入后会重新加载数据**：先出空表单再回填，回填完成前填写会被冲掉。`edit` 会等"保存"按钮出现 + 网络空闲。
- **表单刚打开时默认值异步加载**（如财资中心）：没加载完就保存会"保存失败"，页面顶部会列出错误信息。`open` 已等待。
- **同名菜单被别的菜单项遮挡**：点击前要选真正点得到的那个；菜单展开有动画，需重试。
- **提示（toast）只有几秒且可被关闭**：只能当辅助证据；真正的检查点用界面字段/待办/已完成列表。
- **本机系统代理会让内网地址 502**：浏览器默认直连。

## 6. 流程怎么走
- 提交：点"提交" → 确认框点"提交"。**系统可能接着弹业务提醒**（如余额不足，带"返回/继续处理"），用 `submit_with_warning` 检查并选择。
- 审批：在首页"我的待办"找到单据行，行内"同意"→确认框"同意"；一张单可能连续多个节点，同一审核人逐个处理。
- 被拦截：节点校验失败时提示"执行服务失败！…"，单据仍在待办（`approve_blocked`）。
- 退回：行内"退回"→确认框"退回"（默认退回至制单）。制单人待办里该单据节点变"制单"，点**流程名称**打开单据，工具栏有"提交""编辑"；沿用原单据编号。
- 办结：单据出现在首页"已完成"且不在待办。

## 7. 把材料变成用例：思考顺序
1. 这个功能的**业务目的**是什么？谁用（角色）？
2. 有几种业务分支（类型、选项）→ 每个分支是不是生产里天天会走？是 → 一个主流程场景。
3. 有哪些**核心异常**（被业务规则拦截的、被退回的）？证据：需求异常表、`findMessages` 的真实提示。
4. 每个场景的**业务检查点**：计算结果（利息、天数）、条件显示、拦截提示、流程办结；以后加数据库检查点（单据状态、结果表）。
5. 对照真实界面逐条验证（先 `--draft` 跑通），差异写进 `unconfirmed`。
6. 生成审核页，等业务确认。

## 8. 尚未验证（不要当事实用）
- 业务表数据库检查点：测试库 MCP 的白名单不含业务表，需专用自动化库。
- 表单定义 JSON 的自动获取：代码 MCP 不索引它，目前靠 `ifc forms import` 导入。
- Windows 上的完整运行。
- 复选、开关、单选、页签、日期范围等组件的适配器。

## 补充：选择弹窗、多选币种、字典帮助列、查询页（2026-11-16，dev 真实页面验证）
- **打开即弹出的「选择…」窗口**（银行授信额度变更/终止、企业定存到期指示变更）：antd Modal，里面是另一张表单，带搜索框（提示文字不固定，含「搜索」或「关键字」）、勾选/点行、「确定」「取消」。用 `pick_record` / `expect_not_listed`。
- **币种多选**（授信币种）：点开后选项是多选，必须点弹层里的「确定」才关闭；选中后框内只显示第一项，其余折叠成「+N」。`Currency` 适配器两种都支持，读回时忽略「+N」。
- **网格里的字典帮助列（编辑器码 7）**（授信品种）：点单元格进入编辑 → 单元格内是下拉 → 弹出「编号 名称」表格，点名称所在行。选中后单元格内的输入框是搜索框，值在 `.ant-select-selection-item`，不能读 input。
- **查询页**：条件区是普通 antd 控件；结果表是画布，没有 DOM 文本，用页面「导出」得到 xlsx 读取。条件按标签文字就近找控件：下拉点开选项，多选下拉选完要按 Esc 收起。工具栏上的「查询」「导出」要限定在表单根容器内找，避免点到首页同名按钮。
- **菜单**：三栏结构（左一级 > 中间模块 > 右栏「分组标题 + 功能」）。分组标题（如「企业定存」「单据查询」）不可点，所以四级路径只点第 1、2、最后一级；`db_mcp.py entries` 给出的完整路径可以直接填。
