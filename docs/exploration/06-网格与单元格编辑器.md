## 二、新增与删除行

### 2.1 新增行

- 表单网格（分录/明细）的工具栏新增按钮是动作组件 **`FormAddItemAction`（显示名「增加分录」）**：`osp-react-designer-webcomps/src/actions/FormAddItemAction.tsx:24-28`。
  - 关键属性：`dataModel`（FormModel/FilterDataSet）、`CTN_ID`（分录内容编号）、`ctnType`（JIDS 分录 / JPDS 明细）、`addPosition`（首行/上一行/下一行/末行，默认「下一行」）、`selectInsertedRow`（默认 true）、`isCopyRow`（复制上一行）— `:41-103`。
  - 执行：`doAction` 调 `modelComp.createItem(CTN_ID, bizMetaData, addPosition, '', selectInsertedRow)`（分录）或 `createPart`（明细）— `:187-246`；FormModel 侧按位置 `insertRowSet/insertRowSetByIndex` — `osp-react-designer-pubcomps/src/models/FormModel.tsx:2194-2206`。
  - 脚本钩子 `beforeAdd`（返回 `'0'` 取消）、`endAdd`（参数 addEFRowSet）— `FormAddItemAction.tsx:22,211-245`。
- `AGGridAddItemAction`（显示名「分级字典增加」）是分级字典/树表用的，不是单据分录网格的新增按钮：`actions/AGGridAddItemAction.tsx:13-18`；其 `isAppend`/`isAddFirstLine` 决定位置 `:149-163`。
- 工具栏渲染：GridToolBar 把 `actionList` 里每个动作渲染成 `FormImageButton`（props 含 `labelText = actionText`、`action = 动作 key`）— `osp-react-designer-webcomps/src/ui/GridToolBar/index.tsx:92-142,297-310`。按钮稳定标识：按钮文本「增加分录」（默认 actionText）或动作 key；DOM 类名未读（未确认）。
- 新行位置：数据集先插入，再经 `GridDataSetBridge.doGridDataSetInsertHandler` 以 `applyTransaction({add, addIndex})` 加到网格，并默认 `rowNode.setSelected(true)` + `ensureIndexVisible`（`selectInsertedRow !== false` 时）— `W/GridDataSetBridge.tsx:80-139`。临时新增行最终位置由 `postSortRows` 决定（追加到创建页的正式数据之后）— `W/GridDataSetBridge.tsx:85-89`，`W/AGGridPre.tsx:3081`。
- **新行不会自动进入单元格编辑状态**：源码中 `startEditingCell` 仅出现在 `AGGridPre.startEditingCell()`（公开 API，供脚本调用）和「上下文变化后恢复编辑」`restoreEditingCell` — `W/AGGridPre.tsx:1726,3701-3726`；新增路径 `GridDataSetBridge`/`FormAddItemAction` 内没有调用（`grep` 无命中）。新行只是被选中；单击单元格才进入编辑（见三）。**表单脚本的 `endAdd` 里可能调用 startEditingCell，属表单个性，需看具体 JSON（未确认）。**
- `asyncInsertRow`（异步添加行，默认 false）：开启时改用 `applyTransactionAsync`（ag-grid 批量异步事务，回调里刷新排序、选中并定位、刷新 `#RowNum`），否则同步 `applyTransaction`。用于「同时多次插入新行」避免多次派发事件导致渲染问题，官方提示「不建议使用，可能卡顿」— `W/GridDataSetBridge.tsx:114-139`；属性定义 `osp-react-designer-webcomps/src/ui/AGGrid.tsx:659-666`。自动化含义：开启后新行 DOM 出现有异步延迟，必须轮询等待行数增加。

### 3.2 编辑器 DOM 外壳

所有编辑器外层 `div` 点击时 `stopPropagation` 并 `setCellEditorClicked(true)`，避免触发 rowClicked。编辑器内部元素约定：
- 外层容器类 `${compId}-container`，内部控件类/id 含 `compId`。
- `compId = formID-列组件key-数据集ID-dataSetColID`（`formID` 取 `modelContainer.formID`，空则取 `forms`）— `W/celleditor/util/tool.js:1-13`。**这是定位某列编辑器最稳定的类名**，下拉弹层类名也带它（`${compId}-dropDown` / `${compId}-parallel`）。
- 编辑器自带 `<style>` 标签，无业务意义。

### 3.3 提交时机（重点）

编辑器有两层「提交」：

1. **即时写 RowSet（输入/选择当下）**：各编辑器在 `onChange` 里立刻 `CellEditorUtil.updateRowSet(...)`，写入 `rowSet.putValueWithEvent('${dataSetID}.${dataSetColID}', 值)` 并派发事件 —— 文本 `W/celleditor/GridTextInputEditor.tsx:67-74`；数值 `GridNumberInputEditor.tsx:348-420`；下拉掩码 `GridComboBoxEditor.tsx:56-65`；下拉帮助 `GridHelpComboBoxEditor.tsx:79-117`；字典帮助 `GridDataSetFieldComboBoxEditor.tsx:404-475`；日期 `GridDateFieldEditor.tsx:161-202`；`util/CellEditorUtil.tsx:112-157`。所以**值在选中/键入那一刻已进入数据集**，不必等失焦。
2. **ag-grid 结束编辑（stopEditing）**：编辑器 `getValue()` 被取走，网格触发 `onCellEditingStopped` → `CellEditorUtil.finishEdit`（执行单元格编辑管理器 `finishEdit` 脚本，可能再改其他单元格值）→ `validateCell` — `W/AGGridPre.tsx:2218-2235`。

结束编辑的触发源：
- **点击网格外/非单元格元素**：文档级 click 监听，若目标不是 `role=gridcell/presentation` 或点在 `.osp-center-cols-viewport` 空白区，则 `gridApi.stopEditing()`；但**自定义弹出帮助（30）弹窗期间不允许结束**（`getShouldStopEdit()` 返回 false）— `W/AGGridPre.tsx:1446-1470`；`W/celleditor/GridCustomHelpFieldEditor.tsx:54-56`。设计模式不注册该监听。
- **回车 / Tab / 点其他单元格**：ag-grid 默认行为（Enter/Tab 结束编辑并移动焦点；点另一单元格会结束当前编辑），源码里未重写，**属 ag-grid 默认，未在页面验证（未确认）**。例外：回车处理 `suppressKeyboardEvent`——编辑中按回车，若列编辑器码属于 `ospGridConfig.selectValueWhenEnterPressEditors` 或码为 `'47'`、**`'7'`（字典帮助）**，则不走默认回车，改为 `requestAnimationFrame(() => api.stopEditing())`（下一帧结束编辑）并吞掉回车 — `W/GridUtil.tsx:465-480`。
- 数值编辑器的 `getValue()` 内置校验（非数字清空、小于下限回退），且在切换单元格时「可能先取值再卸载」所以不能只依赖 onBlur — `GridNumberInputEditor.tsx:214-243`。
- 脚本/程序化：`stopEditing()`（`AGGridPre.tsx:1701`）；容器变化前 `captureAndStopEditing` 会先停止再 `restoreEditingCell` 用 `startEditingCell` 恢复 — `W/AGGridPre.tsx:1691-1730`。

debounce/异步：
- 值写入本身同步，无 debounce。字典帮助（7）的搜索输入在 `isManuallyInput=1` 时有 100ms `setTimeout`；下拉帮助滚动分页有 500ms debounce；下拉/字典帮助的选项**需异步请求字典数据**（`MDModel.loadByParam`）— `GridDataSetFieldComboBoxEditor.tsx:536-551`、`GridHelpComboBoxEditor.tsx:297-306`。
- 下拉帮助（21）选项在编辑器挂载时（`useEffect`）加载；默认走网格级缓存 `getFKeyDataSetMap()`，命中则同步出选项，未命中异步请求 — `GridHelpComboBoxEditor.tsx:144-181`。**首次打开可能选项尚未加载，必须等待选项出现**。
- 编辑器首次聚焦：`autoFocus = 焦点单元格 colId === 当前列 key` — 各编辑器末尾；`startEditingCell` 内部先 `setFocusedCell`，再 `setTimeout` 启动编辑 — `W/AGGridPre.tsx:3715-3725`。

## 七、多网格区分

- 组件自身标识：每个网格有表单里的唯一 `key`（`props.base.key`，即表单 JSON 节点 `key`）。

## 对自动化的难点

1. **类名前缀非标准**：`osp-` 而非 `ag-`；col-id 是 Column key 而非 dataSetColID，需先从表单 JSON 建立映射。
2. **行无稳定 ID**：`row-id` 是随机 uuid，只能靠 `row-index` 或新增前后差集定位。
3. **新增行默认不进入编辑**：需要再单击单元格；`singleClickEdit`/`rowSetEdit`（默认整行编辑）会让整行出现多个编辑器，要按 col-id 在当前行内选对应编辑器，避免串列。
4. **下拉类编辑器显示编码/名称不一致**：聚焦后显示编码，失焦显示名称；真实值是编码，显示文本是名称（字典码 7/21 还会因 `ShowCode` 变化），断言要区分「显示文本」与「数据集值」。
5. **选项异步加载**：字典帮助/下拉帮助的选项要网络请求（`LargeDICTService`），首次打开需等待；`asyncInsertRow` 开启时行出现也是异步。
6. **字典帮助是 `@panui/fi` 的 ParallelCode**：弹层是表格而非普通 antd Select 下拉，内部 DOM 与交互（回车被特殊处理、搜索不按空格拆词）需单独标定；多选需 `CheckBox=1`。
7. **提交时机分层**：值在选中/键入时已写入数据集，`stopEditing` 才触发 `finishEdit` 脚本与联动（`AutoSetCols`、单元格编辑管理器脚本可能改其他列/回退）；填完一格后应触发结束编辑（点网格外空白区或按回车）并等待联动完成再读回。
8. **点击行为陷阱**：编辑器内点击会被 `stopPropagation` 且置 `cellEditorClicked`，会吞掉下一次 rowClicked；点击网格外会结束编辑（自定义帮助 30 弹窗期间除外）。
9. **数值列**：编辑框是文本框并带校验/精度/折算，输入不合法值会被清空或回退；非编辑态显示是格式化文本，读回断言需用数据集值或自行去千分位。
10. **只读判断依赖多层条件**（网格可编辑 + 列 editable + 激活表达式 + 单元格编辑管理器 + 合并/只读），DOM 上的灰底/角标类依赖表单开关，最稳的做法是尝试单击并观察是否出现 `.osp-cell-inline-editing`。
11. **码 30 弹出另一张表单**：需要处理模态窗口及其内部选择，不能当普通输入。
12. 分页占位行、临时新增行、列脚行、`blank_column` 尾部空白列都会出现在 DOM 中，遍历行/列时要过滤。
