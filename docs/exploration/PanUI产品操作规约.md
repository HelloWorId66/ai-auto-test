## 3. 对测试框架有约束力的结论

**表单元数据**（02）
- 表单定义是 `WEB-INF/ReactFormSpace/<FormID>.json`，通过 `/rest/react/loadjson` 加载，后端回退顺序为磁盘、jar 包、数据库。数据库回退只在 `saveJSONForm2DB=1` 时启用。
- 全仓没有 `form_designs` 这个名字，早期方案里的说法作废。
- 字段标签、必填、只读、掩码、数据集列都在 JSON 的 `props` 里，可以不开浏览器离线解析。
- 页面看到的 JSON 可能和磁盘 JSON 不一致（前端缓存、个性化改写），重要比对以接口拉取结果为准。

**定位与等待**（01）
- 文本、数字、日期、单选等组件没有稳定 id，定位靠表单 JSON 的控件信息加标签文本、placeholder。
- 下拉类组件的 id 和弹层类名是随机 uuid，弹层挂在 `body` 下。
- 网格选择器只能用 `-pan-grid`，源码里另一个类名 `pan-gird` 是拼写错误。
- 800ms 的输入防抖、按钮 300ms 防抖、分页和工具栏轮询，决定了不能用固定 sleep，要按等待点写专用等待。

**流程反馈**（03）
- 成功和失败提示可以被配置关闭（`showSuccessInfo`、`showFailInfo` 为 '0'），“验”不能依赖提示文案。
- `MessageBox` 约 3 秒消失，多个提示可能叠加。
- 任务被别人处理会返回 `NO_PENDING_TASK`（0x0002），并行测试要保证每个场景独占自己的单据。

**业务落库（通用机制，04 §1）**
- 流程编号即流程类名；每个流程类继承 `FlowMovementAbstract`，在 `initParam()` 里声明单据头表、主键列、状态列。全仓 340 个流程类，其中 318 个能用 `tools/discover_bill.py` 自动提取出完整的三要素，覆盖 BM、FX、LN、LM、PI、FT、TF、DP、DA、BI、CF 各业务域。
- 基类的单据头状态通用值：1 制单、2 审批中、3 审批完成、4 作废。**前提是该流程没有覆盖基类行为**；`initParam()` 把状态列显式设为 null 的有 18 个流程，不能用「状态=3」判断审批完成，要另找完成标志。
- 审批完成后写哪些业务表，是每个流程在 `processSubmitToEnd` 里自己写的，没有统一规律，要读该流程的代码。这一步不能自动化，也不能靠经验猜。
- 状态值用代码常量，不要把中文状态写进 SQL。当前库里查不到单据头状态的展示映射。
- 具体模块的落库事实不放在本规约里，放在 工作区 `knowledge/modules/<模块>-<业务>.md`（案例），见 工作区 `knowledge/modules/README.md`。

## 4. 核对中发现的勘误与风险

1. 04 里两个样本模块的具体勘误已移到 工作区 `knowledge/modules/` 对应案例文档。
3. 02 §4.4 的 `EditorTypeConstrants` 扩展名应为 `.tsx`；§1.2 的 `JarFileUtil.java:46-69` 指单参数版本；§2.4 的 `savejson` 在 609 行。
4. 01 的 `BaseElementControl.tsx:127-131`、`GridToolBar/index.tsx:65-73`、`FormDateField.tsx:516-518` 行号偏移较大，结论成立。
5. 03 §4.1 批量处的键名是 `AllowSameUserOperateNeighborNode`（首字母大写），和单个处理的小写不同；§4.2 取回方法实际有 `retakeInTasklist1`、`retakeInTasklist2` 和 `retakeInTasklist`。

6. 解析真实表单发现：网格的列模型（`ColumnModel`）常嵌在 `dataModels` 的 `Folder` 里，不在第一层；工具栏的保存、提交、同意等按钮不是 `FormButton`，而是 `GridToolBar.actionList` 引用的动作组件（`GeneralAction`、`FlowSubmitAction` 等），按钮的可见性由动作的 `visibleExpression` 决定。
7. 01 没有覆盖 IFC 业务组件（`osp-react-department-webcomps`），已补充 `05-IFC业务组件.md`（抽查 7 处引用行号均吻合，偏差 ±2 行）。`FormRadio` 实际由 `DepFormRadio` 提供，与 01 里的 `FormRadioButtonGroup` 同 type 但不同实现。
