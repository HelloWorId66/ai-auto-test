## 1. 动作全景与后端接口

所有流程动作最终都经 `FlowDriverManager`（`actions/util/FlowDriverManager.tsx:13-122`）以 `DAL.IOM('FlowTaskService', '<方法>', PO, cb)` 调用后端；启用"流程操作与服务执行解耦"时改调 `*Decouple` 方法（`FlowDriverManager.tsx:24-31`）：

| 动作 | 组件(type/opType) | breakTaskType/opType | 后端 IOM 方法 |
|---|---|---|---|
| 流程提交 | FlowSubmitAction / SUBMIT_FLOW | — | `submitTask`（FlowDriverManager.tsx:24-31） |
| 流程重置（退回制单，可选是否重审） | FlowResetAction / RESET_FLOW | 0 | `breakTask`（FlowDriverManager.tsx:39-46） |
| 流程取消/撤销 | FlowCancleAction / CANCLE_FLOW | 1 | `breakTask` |
| 流程结束/终止 | FlowEndAction / END_FLOW | 2 | `breakTask` |
| 流程退回（上一节点） | FlowRollbackAction / ROLLBACK_FLOW | — | `rollBackTask`（FlowDriverManager.tsx:57-64） |
| 流程取回 | FlowRetakeAction / RERAKE_FLOW | — | `retakeTask`（FlowDriverManager.tsx:71-77） |

   - PO 关键参数：`OP_LEVEL='00'`、`OP_PROC_NOTE=<意见>`、`FLOW_ID/NODE_ID/EDGE_ID/OBJ_GUID/BIZ_UNIT/BIZ_DATE/BIZ_DJBH/OP_ID/TASK_UNIT`、`DeviceType='Submit'`（:304-368）、`N2N_TASK_TO_USER`（指定审批人，:338-341）。

## 3.「批」审批同意/驳回的语义

PanUI 没有"同意/驳回"专用按钮：**审批同意 = 待办打开单据后点"流程提交"（意见默认"同意"）或待办列表批量提交（`submitInTasklist` 默认 defMsg="同意"，`FlowSubmitUtil.tsx:532-545`）**。

**驳回 = 流程退回或流程重置**：
- `FlowRollbackAction`（退回上一节点）：入口 `FlowRollbackUtil.tsx`，任务缺失/开始节点/自循环分别报错"没有要退回的任务！"(75)、"开始节点无法退回任务！"(90)、"自循环节点的任务不允许退回！"(97)；弹 `FlowActionWindow`（选目标节点+意见，:183、285 `setOpType('rollBackTask')`）→ `FlowDriverManager.rollBackTask`（:466）。
- `FlowResetAction`（重置到制单）：见 §4。

## 4.「变」终止/撤销/取回/重置

### 4.1 重置/取消/结束（FlowBreakAction 家族）

`FlowBreakAction.doAction`（`FlowBreakAction.tsx:69-195`）：
1. `canFlowActionEnable = FlowActionUtils.canEnd`（:236-238；`FlowActionUtils.tsx:49-94`：无任务/非 pending/非默认或事后协审任务类型 → 按钮置灰）。
2. `onlyStartNodeEnd`（结束默认 true）时非 start 节点 → `MessageBox.warning('只有开始节点允许结束操作!')`（:113）。
3. opTastSource='flowModel'（默认）直接 `FlowResetUtil.doTask`；='flowService' 先 `FlowTaskService.queryPendingTask` 取任务再 doTask，取不到报"未取到流程任务!"（:120-193）。
4. `FlowResetUtil.doTask`（`FlowResetUtil.tsx:46-216`）：
   - 无任务 → "任务不存在！"（:56）；`allowSameUserOperateNeighborNode='0'` 且最后任务提交人=当前用户且非取回 → "相邻节点不能处理自己提交的单据！"（:60-68）。
   - isProMsg=true：重置(0) 先 `FlowDriverManager.getBimFlow`（FlowIOService.getBIMFlow，:95）再弹 `FlowResetModal`（:558，含"退回后是否重新审批" resetType 选项，resetType='0' 走 `handleResetAppointorTaskOK`→`assignTask`，TASK_TYPE='6' 不重审，:569-623）；取消/结束(1/2) 弹 `ProMsgModal.showMsgModal('审批意见', defMsg, ...)`（:156-201），确认后 `handleResetTaskOK`。
   - isProMsg=false 直接 `handleResetTaskOK`。
5. `handleResetTaskOK`（:248-377）组装 PO（同提交关键字段，`OP_TYPE_NAME` 由 promptMsgType 或默认"作废"，:400-407；DeviceType='Break'，:333）→ toast「正在处理...」→ `FlowDriverManager.breakTask`（:366）。
6. 结果 `handleResetTaskSuccess`（:378-415）：`FlowResult.code==0` → 更新 nodeTaskDataSet、回写单据字段 `updateBillDatas`（:390-393）、执行 successedFunction、`showFlowMessage`；异常 → `MessageBox.error('流程重置异常！')`（:413）。

## 5. 批量动作（待办列表勾选多行）

以 `FlowResetUtil.breakInTasklist`（`FlowResetUtil.tsx:673-819`）为例：
1. 逐行校验：外部系统任务(SYS_TYPE='EXT')拆到 ExtData（:698-716）；相邻节点本人提交 → FormAlert"单据[x]:相邻节点不能...自己提交的单据！"（:722-736）；TASK_TYPE='3' 查看任务 → "只能查看不能被处理！"（:738-747）；前加签/沟通任务 → 不能处理（:749-757）。**任一行校验失败即中止整个批量**。

4. 每单结果 push 进 msgarray，**全部返回后**（`msgarray.length===total`，:979）合并成一个 `FormAlert.showAlert` 汇总弹窗（MESSAGE_NORMAL/WARN，:1016-1021）。

## 7. 成功后的提示与页面跳转（等待信号核心）

`FlowActionUtils.showFlowMessage`（:932-1105）+ `getFlowMessage`（:892-931）：

- 成功/失败提示受 `showSuccessInfo`/`showFailInfo` 开关控制（`BaseFlowAction.tsx:175-217`，ModelContainer 可配 '0' 关闭；`FlowActionUtils.tsx:34-38` 传入 infoMap）——**自动化不能假设一定有提示弹窗**。
- 成功路径三种展示（`FlowActionUtils.tsx:1037-1101`）：
  1. 环境变量 `closeTabAfterSubmit='1'` 且 opTypeName=="提交" 且文案含"成功" → `MessageBox.success(msg,3)` + `window.closeCurrTabInReact()` 关闭当前页签（:1055-1060）。
  2. `selectISCloseTabAfterSubmit='1'`（且非取回）→ 弹 `FlowShowMessageWindow`（带"是否关闭单据"复选框，:1060-1072）。
  3. 默认 → `MessageBox.success(msg, 3)`（3 秒自动消失，:1098）。
- 失败 → `MessageBox.warn(msg,3)`（:1104）。
- 待办环境（QueryType=='FLOW_Pending'）且开启 `Flow_AutoOpenNextBillAfterApproval='1'` → `InfoMsg.success(msg,5000,'topRight')` + `closeCurrTabInReact()` 自动开下一单（:1015-1033）。
- 结果数据回写：成功后后台返回 billUpdateFieldVaules 回写表单字段（`FlowResetUtil.tsx:390-393`，`FlowActionUtils.updateBillDatas` :777）。
- 待办列表操作后列表刷新：`dataSetComponent.load()`（`PendingSubmitAction.tsx:190-198`）。

**等待信号规律（自动化建议）**：
1. 弹窗类：处理意见/审批人选择/重置方式弹窗 → 等待其消失（点击确定后 code=='0' 继续链路）。
2. 过程类：toast「正在提交.../正在处理.../正在处理，请稍候...」start→stop，是可靠的请求完成边界。
3. 结果类：`MessageBox`（3s 自动消失，文本含"成功"/失败原因）或 `FormAlert` 汇总（批量）。
4. 页面类：`window.closeCurrTabInReact()` 页签关闭（取决于环境变量）；表单字段值被 billUpdateFieldVaules 回写；列表 `load()` 重查。
5. 推荐断言顺序：toast 消失 → MessageBox 文本 → 列表/表单数据变化；并按环境变量分支处理（见 §10 难点）。

## 11. 自动化最难的点

1. **分支由环境变量决定**：同一"提交成功"在不同环境有 3 种走向（关页签/弹询问窗/普通提示），等待策略必须先读取环境参数或做兼容性等待（任一信号出现即继续）。
2. **提示可配置关闭**：`showSuccessInfo/showFailInfo` 为 '0' 时无任何弹窗，成功与否只能靠数据状态/列表刷新判断——"验"原语不能依赖提示文案。
3. **弹窗是 ReactDOM 手动挂载**（`document.body.appendChild(div)` + `ReactDOM.render`，如 `FlowResetUtil.tsx:531-558`、`ProMsgModal.tsx:116-155`），无固定容器 id 之外的可预测 testid；`#bsuserSelect`、`#opinionMaintenanceSelect` 是仅有的稳定挂载点。
4. **MessageBox 3 秒自动消失**：失败信息一闪而过，截图或轮询窗口期短；且多个 MessageBox（警告/成功/汇总）可能叠加。
5. **批量操作是循环逐单请求**：逐单返回、最后才弹汇总 FormAlert；中途某单失败整体 error_code=-1 但已成功的单据不会回滚——断言需逐单核对而非只看汇总。
6. **SpreadJS 查询视图**：Canvas 渲染，DOM 断言无效；需走 SpreadJS 实例 API（getActiveSheet/getValue）或导出文件比对；滚动加载无页码语义。
7. **任务状态竞争**：NO_PENDING_TASK（0x0002）"可能已经被其它用户处理"意味着并行测试互相踩任务，用例需独占单据数据。
8. **错误码→文案非一一映射给用户**：部分失败直接展示后台 message（:956,1006-1013），断言文案脆弱，建议断言 code 或结构性信号。
