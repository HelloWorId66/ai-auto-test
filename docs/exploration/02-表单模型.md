# 02-表单模型：表单定义的存储、加载与控件映射

> 探索日期：2026-11-13。所有结论均回本地源码核证，证据格式 `文件:行号`。
> 涉及仓库：`04.osp/osp-lcdp-parent`（平台后端）、`04.osp/ifc-6.5-react-webapp`（前端）、`01.server/IFCSpringService`（部署产物）、`00.code/*`（业务服务仓）。

## 0. 结论速览

1. **表单定义不是叫 form_designs 的表**——它是一个以 FormID 命名的 JSON 文件，存放在服务端磁盘 `WEB-INF/ReactFormSpace/` 目录；`form_designs` 这个词在源码中不存在（全仓 grep 无命中，batch1 探索同样确认）。
2. 加载链路：菜单(`/rest/react/menu`) → `menuItem.config.forms` → 前端 POST `/rest/react/loadjson` → 后端按 文件系统 → jar 包 → 数据库 三级回退返回 JSON → `FormRender` 解析 `components` 树渲染。
3. 控件映射：JSON 里每个节点的 `type` 字符串（如 `FormTextInput`）经 `ElementFactory` 静态注册表找到 React 组件类；组件类用 `@staticMembers({type, displayName, category, props:[...]})` 声明自己。
4. 字段语义（标签/必填/只读/掩码/数据集列）全部在 JSON 的 `props` 里，**无需启动浏览器即可离线解析**——这是"不让 AI 猜字段"的关键。
5. DOM 无稳定字段 id：组件渲染不输出 `id={key}`，自动化定位须靠标签文本/placeholder/CSS 类名（见 §6）。

## 1. 表单定义存在哪里（存储三级 + 前端缓存）

### 1.1 第一级：服务端文件系统（主存储）

`osp-lcdp-parent/osp-platform/osp-platform-form-manager/src/main/java/com/efounder/server/flex/restful/ReactJsonService.java`：

- 默认目录：`EAI.LocalUserHome + "WEB-INF/ReactFormSpace"`（ReactJsonService.java:69）。
- 多应用隔离：开启 appId 后目录变为 `WEB-INF/ReactFormSpace_<appId>`（getFormFileLocationWithAppId，ReactJsonService.java:1622-1640；getFolderNameWithAppId，1647-1653）。
- 多语言：中文 `zh_CN` 直接用原文件；其他语言存 `WEB-INF/ReactFormSpace_<lang>/<formID>_<lang>.json`（loadJson2 内 IFC 定制分支，ReactJsonService.java:309-314；保存侧 saveReactJson4MultiLanguageIFC，787-839，中文跳过在 811）。
- 文件名 = `<FormID>.json`（getFormFilePath，ReactJsonService.java:1603-1615）。
- 保存时自动备份最近 20 份到 `WEB-INF/ReactFormSpaceBak/`（BACKUPCOUNT，ReactJsonService.java:93；backupFormJsonFile，1563-1595）。

**实证**：本机部署产物 `IFCSpringService 部署产物 WEB-INF/ReactFormSpace/` 下有 1322 个 JSON（如 `LmEnterpriseCreditLineChangeForm.json`、`BankAccountBalanceInput_React.json`），并有 `ReactFormSpace_en_US/`、`ReactFormSpace_zh_HK/` 目录，与代码一致。

### 1.2 第二级：jar 包内（产品内置表单）

文件系统找不到时回退到 jar：`JarFileUtil.getReactFileFromJar(fileName, appId)`（ReactJsonService.java:328-337、346-358）。

`osp-lcdp-parent/osp-base/osp-base-core/src/main/java/com/efounder/util/JarFileUtil.java`：

- jar 内路径固定 `file/ReactFormSpace/<FormID>.json`（REACT_FORM_PATH，JarFileUtil.java:32；getReactFileFromJar，46-69；带 appId 时 `file/ReactFormSpace_<appId>/`，65）。
- jar 资源加载器依次尝试 `com.efounder.file.BaseFile`（osp-base-file）→ `com.ifc.file.FlowBaseFile`（IFC 流程包）→ `com.ifc.file.MessageCenterBaseFile`（消息中心包）（getURL，JarFileUtil.java:111-136）。

**实证**：业务仓自带表单资源 `00.code/SYS/ZJFlowService/src/main/resources/file/ReactFormSpace`、`00.code/SYS/ZJMessageCenterService/src/main/resources/file/ReactFormSpace`、`00.code/FX/ZJForeignExchangeService/src/main/resources/file/ReactFormSpace`——即部分系统表单随业务服务 jar 发布。

### 1.3 第三级：数据库（开关 `saveJSONForm2DB=1` 才启用）

- 读取：`FlexFormLoad.loadFormFMTByFormIDFromDB(PO, formID, "FORM_JSON_FMT")`（ReactJsonService.java:361-373）。
- 保存：`FlexFormSave.saveFlexForm2DB(conn, PO, formCTNMap, "FORM_JSON_FMT")` 写入 **SYS_FLEXFORM_FMT** 表（saveReactJson2DB，ReactJsonService.java:1414-1440，关键行 1428-1431）。
- 表单注册表 **SYS_FLEXFORM**（FORM_BH/FORM_MC/FORM_DES/FORM_TYPE/SYS_ID/F_CRUSER/F_APPID/FORM_GROUP；插入 SQL 在 ReactJsonService.java:1252-1263；重名检查查 `SELECT * FROM SYS_FLEXFORM WHERE FORM_BH = ?`，1167）。保存日志表 **SYS_FORMSAVE_LOGS**（1321-1328），最后保存时间 `SELECT MAX(SAVE_TIME) FROM SYS_FORMSAVE_LOGS WHERE FORM_ID = ?`（1533-1557）。
- 服务端脚本（表单内嵌 JS 的服务调用名）单独落 `WEB-INF/SQLProperties/<FormID>.properties` 及 SYS_FLEXFORM_FMT.FORM_PRO_FMT（json2properties，1449-1504；saveReactPro2DB，1893-1922）。

> 注：ifc-db MCP 白名单不含 SYS_FLEXFORM，未能对库直查；表结构以源码 SQL 为准。

### 1.4 前端 IndexDB 缓存（对测试的影响）

`osp-react-base/src/api/reactForm.tsx`：前端把返回的表单 JSON 按 md5 `sign` 缓存进浏览器 IndexDB；请求带上次 sign，服务端内容未变时返回 `code=2`，前端直接用缓存（reactForm.tsx:40-69、116-124）。**自动化测试若复用浏览器 profile，可能拿到旧表单**；直连 HTTP 拉取则不受影响。

## 2. 前端如何请求并渲染表单（数据流）

### 2.1 菜单 → 表单 ID

- 菜单接口：POST `/rest/react/menu`（`osp-react-base/src/api/menu.tsx:38-39`，参数含 SYS_ID/UserName/Lang/ospAppId）。
- 菜单项 `config.forms` 或 `config.formID` 携带表单编号（多个用逗号分隔：主表单,子表单）；`config.serverID` 指定后端服务。见 `osp-react-formbuilder/src/routes/reactForm/index.jsx:136-152` 与 `osp-react-formbuilder/src/utils/FormUtil/reactForm.jsx:93-113`。
- 菜单数据源头是平台菜单表（BSGNZD/SYS_VERITY_TREE），本篇不展开（见流程/菜单探索文档）。

### 2.2 取表单 JSON：POST `/rest/react/loadjson`

`osp-react-base/src/api/reactForm.tsx`：

- URL：`${baseUrl}/rest/react/loadjson`，POST，请求头带 `Ospformid: FormID`（reactForm.tsx:71-77）。
- 请求体：`serverID`、`FormID`（含子表单时逗号拼接，80）、`SYSLang`、`MultiLanguage`、`sign`（上次 md5）、`userName`（JParamObject）、`ospAppId`、以及菜单 config 展开项（reactForm.tsx:70-85）。
- 后端响应：`{code, message, data, sign}`；`code` 0=失败 / 1=返回新 JSON / 2=未变化用缓存（createResult 注释，ReactJsonService.java:1857-1885）。多 FormID 时后端并发加载，返回 `{formID: {...}}` 字典（loadJson，ReactJsonService.java:217-261）。
- 加载结果 JSON.parse 后交给渲染器：`utils/FormUtil/reactForm.jsx:83-84`（`setJsonSchema(JSON.parse(data.data))`）。

### 2.3 渲染入口

- `utils/FormUtil/reactForm.jsx:2` 引入 `import { ReactForm as FormRender } from 'osp-react-designer-core'`；:122 `<FormRender jsonData={jsonSchema} menuItem={menus} />`。
- `osp-react-designer-core/src/formrender/ReactForm.tsx:34-43`：ReactForm 仅包一层水印/国际化，真正渲染在 `FormRender.tsx`。
- `FormRender.tsx` 构造时把 `menuItem`（含 config）逐键注入 `modelContainer`（FormRender.tsx:76-87）——表单脚本通过 `modelContainer.getValue('BIZ_DJBH')` 等读菜单参数，这是"新增/详情"差异的来源之一。

### 2.4 设计器专用接口与扩展点

- POST `/rest/react/loadformdata`：与 loadjson 相同的查找逻辑，额外返回 `lastSaveTime`（右键设计表单用；ReactJsonService.java:508-574）。
- 其他同族接口：`/rest/react/savejson`（608）、`/rest/react/checkexist`（1129-1154）、`/rest/react/loadJsonAndProperties`（130-210，导出 json+properties zip）。
- 个性化扩展钩子：系统参数 `expandJsonFormService` 指定的服务可在返回前改写 JSON（getExpandJson，ReactJsonService.java:582-601，IFC 传入 FORM_JSON_STR 在 590-592）。**测试拉到的 JSON 可能已被该服务改写**。

### 2.5 鉴权

- 登录：POST `/osplogin`（form-urlencoded；`osp-react-base/src/api/login.js:9-17`）；登出 `/logout`（19-24）；验证码/短信 `/code/sms/send`、邮箱 `/code/email/send`、二维码 `/createLoginQRCode`（35-53）。
- token：`/token/check` 校验 osptoken（`osp-react-base/src/api/token.js:7-18`）；**机器对机器通道** `/token/produce?clientId=...&clientSecret=...`（或 newApi 下 `/token/formPlayProduce`，token.js:20-40）——formPlay 独立表单播放页使用（`osp-client-app/src/router/index.js:213-241`）。这为无头拉取表单 JSON 提供了绕开 UI 登录的可能（需环境配置 formPlay.clientId/clientSecret，未确认各环境是否开放）。

## 3. 表单 JSON 结构（真实样本实证）

样本：`IFCSpringService 部署产物 WEB-INF/ReactFormSpace/LmEnterpriseCreditLineChangeForm.json`（企业授信额度变更表单）。顶层键：

| 键 | 内容 | 样本值 |
|---|---|---|
| `key` | 根组件 key | `RootPage` |
| `formName` / `formID` | 表单名/编号 | `企业授信额度变更` / `LmEnterpriseCreditLineChangeForm` |
| `lastAuthor` / `lastChanged` / `version` | 元信息 | `0001` / `2026-08-28 11:02:18` / `React` |
| `rootProps` | 根页面属性 + `scriptsCode.componentDidMount` 根脚本 | — |
| `components` | **可视组件树**（数组，单根） | 见 3.1 |
| `dataModels` | **模型组件数组**（数据模型/列模型/校验器） | 见 3.2 |
| `actionComps` | 动作组件数组（按钮行为） | 21 个，如 `ReactFormWindowAction` |
| `serverJsComps` | 服务端脚本组件（落 SQLProperties） | 本样本为空 |
| `tableSource` | 数据集清单 | 见 3.3 |

### 3.1 components 树与字段属性

树节点结构：`{key, type, props, compName, children[]}`。布局容器 `FormBoxContainer`（compName 通用布局）逐层嵌套；字段组件叶子形如：

```
key=FormComponentF_CZRQ  type=FormDateField  compName=日期选择
props: showLabelText="变更日期"   ← 字段标签
       dataSetID="ZJSXHTSQ"      ← 所属数据集码
       dataSetColID="F_CZRQ"     ← 数据集列名（=物理表列）
       dataModel="FormModel1"    ← 绑定的模型组件 key
       enableNotNull=false       ← 必填
       enableNotNullCheck=true / enableNotNullTip="此项为必填项！"
       edit=false                ← 可编辑（false 为只读/禁用）
       placeholder="请选择日期"   / isShowLabel / labelPosition
       scriptsCode={onSelectedChange,onLostFocus,...}  ← 前端事件脚本
       style={width,height,...}
```

（证据：样本 JSON `FormComponentF_CZRQ` 节点 props；字段命名惯例：容器 key `FormBoxContainerF_XXX` + 字段 key `FormComponentF_XXX`，但**这仅是设计器习惯，不是解析器强制约定**，取值仍以 `dataSetColID` 为准。）

### 3.2 dataModels（模型层）

样本含 14 个模型组件，关键两类：

- `FormModel`（单据模型）：`props.providerService="ESPBillProvider"`、`resolverService="BaseLineBillResolver"`、`bizMDLID="ZJSXHTSQModel"`、`billContentID="ZJSXHTSQ..."`（截断）——这是表单与业务模型/落库表的绑定；带 `scriptsCode.endLoad` 等生命周期脚本。
- `BIZMetaDataModel`（单据元数据）：`bizMDLID="ZJDKSQModel"`，供帮助/下拉取元数据。
- 其他：`FormDataChecker`（表单校验器，checkHead/checkPart 脚本）、`FormValueManager`（默认值管理器）、`Folder`（设计器分组，无运行时作用）、`ColumnModel`（列模型，见 3.4）。

### 3.3 tableSource 与数据集码 ↔ 物理表映射

样本 `tableSource`：`[{tableName:"授信额度申请主表", tableID:"!ZJSXHTSQ"}, ...]`。

映射链（DB 实测，ifc-db MCP 查 SYS_MODEL/SYS_MDL_CTN/SYS_MDL_VAL，2026-11-13）：

- `FormModel.bizMDLID="ZJSXHTSQModel"` → SYS_MODEL 行（MDL_MC=授信额度申请模型，MDL_UNITDCT=ZJFZJG 单位字典，MDL_BHDCT=PWBHZD 编号规则字典）。
- SYS_MDL_CTN 每行一个数据集：`CTN_ID`=数据集码（=JSON 里 `dataSetID`），`CTN_FCT1`=物理表名（ZJSXHTSQ 等），`CTN_TYPE` 01=主表 / 02=分录，`PCTN_ID`=父数据集（分录挂主表）。
- SYS_MDL_VAL 存模型键值：`BILL_BH_COL=F_DJBH`、`BILL_GUID_COL=F_GUID`、`BILL_TYPE_COL=F_DJLX` 等单据通用列约定。

即：**离线拿字段→表列语义 = 表单 JSON(dataSetID+dataSetColID) + SYS_MDL_CTN(数据集→表)**。
`tableID` 前缀 `!` 的含义未在源码定位到解释（未确认，不影响解析，dataSetID 去 `!` 后与 CTN_ID 一致）。

### 3.4 网格（分录/子表）列定义

`AGGrid`（compName 业务表格）的列不在自身 props 里展开，而是 `props.columnModel="ColumnModel1"` 指向 dataModels 里的 `ColumnModel` 组件；列定义是 ColumnModel 的 `children`：

```
ColumnModel1.children[n] = { key:"Column42", type:"Column", props:{
  headerText:"操作类型"        ← 列头文本
  dataSetColID:"F_OP_TYPE"    ← 列名
  editorType:"6"              ← 单元格编辑器类型码（见 §4）
  maskConfigKey:"BM_OP_STATUS"← 下拉掩码配置 key（下拉列）
  editable:false / visible:true / width / columnType:"C" ...
}}
```

（证据：样本 JSON ColumnModel1.children；`osp-react-designer-webcomps/src/index.js:11` 导出 ColumnModel。）

### 3.5 actionComps / serverJsComps

- `actionComps`：窗口动作（如 `ReactFormWindowAction`，props 含打开子表单/流程提交配置），是"审批/提交/关闭"按钮行为的元数据来源。
- `serverJsComps`：保存时被抽到 `WEB-INF/SQLProperties/<FormID>.properties`（key=组件 key，value=callFunction，ReactJsonService.java:1511-1526），运行时服务端执行。

## 4. 控件类型 → React 组件映射（桥接 01-组件全集.md）

### 4.1 注册机制

- 注册表：`osp-react-designer-core/src/base/ElementFactory.tsx`——静态 Map 按组件 `type` 字符串存组件类（_elements/_WebUIElements/_WebModelElements/_WebActionElements/_ServerJsElements 等，ElementFactory.tsx:29-49）；`registerElement()`（64-73）。
- 组件自声明：`@staticMembers({displayName, category, type, icon, props:[{name,type,props:{label},default}]})` 装饰器把元信息挂到类上（`osp-react-designer-core/src/base/decorator.tsx:8-15`）。样例 `FormTextInput`：`osp-react-designer-webcomps/src/ui/FormTextInput.tsx:335-340`（type:'FormTextInput'，displayName:'文本框'）。**`props` 数组就是设计器属性面板定义，等于该控件全部可配置属性及其默认值清单——自动化可直接读取推断字段行为。**
- 渲染时按 type 取类：`BaseElementControl.tsx:46` `const Comp = element.getComponent()`；未注册类型渲染 NullElement 并报错"表单中存在未知的组件类型"（42-47）。

### 4.2 运行时注册入口（组件全集的来源）

`osp-client-app/src/config/InitAppConfig.jsx:48-60` 依次注册：

1. `CommonUIComps/CommonModelComps/CommonActionComps` ← `osp-react-designer-pubcomps`
2. `UIDepartmentComps/ActionDepartmentComps` ← `osp-react-department-webcomps`（**IFC/深港业务组件：AmountComp、PaymentUnit、Currency、ApprovalProcess、BillFooterInfo 等**，如 `osp-react-department-webcomps/src/ui/base/AmountComp/index.tsx:586` type:'AmountComp'）
3. `UIComps/ModelComps/ActionComps/ServerJsComps` ← `osp-react-designer-webcomps`（通用控件 ~100 个文件，`src/ui/` 目录；含 AGGrid/FormTextInput/FormDateField/HelpComboBox/FormComboBox...）
4. cubereport 相关 ← `osp-react-cubereport`

设计器侧同一套注册：`osp-react-form-designer/src/register/index.ts:13-31`。

### 4.3 category 数值分段

渲染器按 category 划分组件类别：UI 0-20 / Model 20-40 / Action 40+（`RenderRootPageElement.tsx:319-340` getComps）。01-组件全集.md 盘点组件名时，以各包 `@staticMembers` 的 `type` 值为准——**它就是表单 JSON 里会出现的 `type` 字符串**，两份文档由此桥接。

## 6. 元数据与界面 DOM 的对应（自动化定位依据）

- **无稳定 DOM id**：`FormTextInput` 渲染输出 `<div><Input .../></div>`，不写 `id` 属性（`osp-react-designer-webcomps/src/ui/FormTextInput.tsx:240-300`）；React 的 `key={element.key}`（`BaseElementControl.tsx:96`）不会进 DOM。容器级只有 `formContainerUUID`（FormRender.tsx:66，用于非空提示定位）。
- 可用的稳定锚点：字段 `showLabelText` 标签文本、`placeholder` 文本、组件 CSS 类名（如 `.FormTextInput`）、列头 `headerText`。**测试定位策略应"标签文本→相邻 input"而非"id"**。

## 7. 自动化如何离线读取表单元据（不启动浏览器）

按优先级推荐：

**通道 A：直接读服务器磁盘 JSON（零依赖，首选）**
- IFC 服务端：`<部署目录>/WEB-INF/ReactFormSpace/<FormID>.json`（本机实证 1322 个文件，§1.1）。
- 多语言表单按 §1.1 目录规则取对应语言文件。
- 解析算法：遍历 `components` 树 + `dataModels` 里的 ColumnModel children → 产出字段清单 `{label: showLabelText, col: dataSetColID, dataset: dataSetID, comp: type, required: enableNotNull, readonly: !edit, mask: maskConfigKey, events: scriptsCode 键列表}`。

**通道 B：业务仓源码内 JSON（评审/离线环境）**
- `00.code/<模块>/<服务>/src/main/resources/file/ReactFormSpace/*.json`（ZJFlowService、ZJMessageCenterService、ZJForeignExchangeService 实证，§1.2）。覆盖系统级表单；业务表单大多只在服务端磁盘。

**通道 C：HTTP 拉取（目标环境新鲜度最好）**
- 登录：POST `/osplogin`（login.js:9-17）拿会话/osptoken；或 formPlay 机器通道 `/token/produce?clientId&clientSecret`（token.js:20-40，环境是否配置未确认）。
- 拉取：POST `/rest/react/loadjson`，头 `Ospformid`，体 `{FormID, serverID, sign:'', SYSLang:'zh_CN', userName, ospAppId}`；`code=1` 时 `data.data` 即 JSON 字符串（reactForm.tsx:71-86）。

## 9. 对自动化测试的意义

1. **表单元据是可离线全量获取的**：FormID → 磁盘 JSON（通道 A）即可得到字段/控件/必填/只读/掩码/列定义全集，测试用例生成与断言不必依赖浏览器，也不必让 AI 猜。
2. **字段定位走"标签文本+placeholder"**：无 DOM id，公共操作库的定位器应基于 `showLabelText/headerText` 设计（§6）。
3. **控件类型决定操作方式**：`type`（FormTextInput/FormDateField/HelpComboBox/AmountComp...）+ 列 `editorType` 码表（§4.4）直接给出"文本输入/日期选择/下拉/金额"等交互模式，操作库按类型分发。
4. **必填/只读判断以 JSON 为准**：`enableNotNull`/`edit`（§3.1），辅以 `FormDataChecker.checkHead/checkPart` 脚本里的业务校验（脚本语义需人工或 LLM 辅读）。
5. **数据落点可静态推导**：dataSetID+dataSetColID → SYS_MDL_CTN → 物理表列（§3.3），业务落库断言可直接生成 SQL 目标。
6. **注意缓存与个性化改写**：sign/IndexDB 缓存（§1.4）与 expandJsonFormService（§2.4）可能让"页面上看到的 JSON"≠"磁盘 JSON"，重要比对以拉取接口（通道 C）为准。
