## 1. 全局定位规则（最重要一节）

三种 id 策略并存，Playwright 选择器必须按组件区分：

**A. 稳定 id：`{formID}-{元素key}-form`（compMark 体系）**
- 生成：`window.$createCompMark(props)` = 运行时 `${modelContainer.paramsMap.get('formID')}-${props.base.key}-form`，设计模式后缀为 `-design`（`osp-client-app/src/config/RegisterWindowFun.js:2-13`）。
- 元素 key 即表单 JSON 里控件的 key（`osp-react-designer-core/src/base/BaseCompElement.tsx:13,22`），表单设计 JSON 抓取后可直接拼出选择器。
- 使用者（已逐一 grep 确认）：FormButton（Button className=`formButton ${compMark}`，`ui/FormButton.tsx:455`；ActionGroup 菜单项 id=`${compMark}-${item.key}`，`:197`）、FormCheckBox（组 className=`${compMark}-group`，每个选项 id=`${compMark}-${item.value}`，`ui/FormCheckBox.tsx:331,344,367,372`）、FormTextArea（容器 id=`${compMark}-container` :312、textarea id=`${compMark}` :335）、FormTextPassword（:149,174）、FormTextSearch（id=`${compMark}-input`，`:93`）、FormTimePicker（容器 :162、picker id=`${compMark}-timer` :186）、FormSwitchButton（id=`${compMark}`，`:190`）、FormMonthComboBox（:279,302）、FormPopupButton、FormImageButton、FormSpinner、FormProSelectInput、AGGridPre（PanGrid className 追加 `${compMark}-pan-grid`，`ui/grid/AGGridPre.tsx:3096,3147`）。

**B. 随机 uuid id：每次挂载都变，禁止作为选择器**
- `FormBaseComboBox.getComBoxuuid()` 直接 `uuid()`（`designer-core/src/controls/base/FormBaseComboBox.tsx:29-31`）。FormComboBox/FormComboCheck/HelpComboBox/HelpComboCheck/FormProSelectInput/cascadertree 均在构造函数赋 `this.uuid`（如 `ui/FormComboBox.tsx:49`、`ui/HelpComboBox/index.tsx:83`）。
- 这些组件外层 div `id={this.uuid}`（`FormComboBox.tsx:426`、`HelpComboBox/index.tsx:926`），下拉弹层 `popupClassName={'dropDown'+this.uuid}`（`FormComboBox.tsx:470`、`HelpComboBox/index.tsx:968`、`HelpComboCheck.tsx:704`、`FormComboCheck.tsx:395`）。
- 用途仅限"通过组件实例反查 DOM"：测试代码可先 `id` 定位再断言。写用例时应改用 className（如 `.FormComboBoxComp`）+ 相对 label 的位置。
- FormTabPanel：id=`tabsBox{boxID}-{uuid}`，boxID 与 uuid 都是随机（`ui/FormTabPanel/index.tsx:626`、`designer-core/src/controls/base/FormBaseBox.tsx:18`、`FormTabPanel/index.tsx:88`）。AGGrid 的 `gridElementID='S'+uuid()` 同理（`grid/AGGridPre.tsx:745`），稳定类只有 `${compMark}-pan-grid`。

**C. 完全无 id：FormTextInput、FormNumberInput、FormDateField、FormRadioButtonGroup、FormCustomHelpField、FormLabel**
- FormTextInput 外层 div 无 id，Input className 固定 `font-style-wrapper FormTextInput`（`ui/FormTextInput.tsx:251,288`）。
- FormNumberInput：InputNumber className=`osp-number-input`（`ui/FormNumberInput.tsx:353`）。
- FormDateField：外层 className=`osp-react-designer-pc-formDataField`（`ui/FormDateField.tsx:487`），日期面板 `popupClassName='PopupCalendar'`（稳定，`:516`）。
- FormRadioButtonGroup：antd Radio.Group，无自定义 id（`ui/FormRadioButtonGroup.tsx:270-304`）。
- FormCustomHelpField：外层 className=`form-custom-help-outer-div`（`ui/FormCustomHelpField.tsx:504`）。
- FormLabel：className=`formLabel`（`ui/FormLabel.tsx:280`）。label 与输入框**无 htmlFor 关联**，只能按 DOM 顺序/容器相邻关系定位。

**D. 表单根容器**：`<div tabIndex={10000} id={formContainerUUID}>`，UUID 在 FormRender 实例化时随机生成（`designer-core/src/formrender/FormRender.tsx:56`、`designer-core/src/controls/ui/PageComponent/RenderRootPageElement.tsx:383`）。所有必填 tooltip、toast 都挂载在该容器内（§7）。每个表单一个容器 → iframe/多表单页面按容器限定作用域即可。
- 注意：React 元素上的 `key={element.key}` 只是 React key，**不会出现在 DOM**（`designer-core/src/formrender/BaseElementControl.tsx:127-131`），不能用 `[data-key]` 选择器。

**推荐选择器模板**：优先 `#前端控件key可拼的compMark`（A 类）→ `getByRole/getByText` → class + 容器内相对位置（C 类）。

## 2. 输入类组件（文本/数字/日期）

### 2.1 FormTextInput 文本框（type: 'FormTextInput'，设计器名「文本框」）
- DOM：外层 div（无 id，flex 布局 + 内联 margin）→ antd `<Input className='font-style-wrapper FormTextInput'>`。前后缀图标为 `<img>`；addonBefore/After 渲染为 antd input-group。
- 赋值：实例方法 `setValue(v)` 写 `inputValue` + 同步 rowSet `putValueWithEvent('dataSetID.dataSetColID', v)`（`designer-core/.../FormBaseDataComp.tsx:129-139`）；页面交互用 `page.fill('input')` 触发 onChange。**注意 onChange 有 800ms debounce**（`FormTextInput.tsx:306` `lodash_debounce(this.changeFun, 800, {leading:true})`）——Playwright 填完后需等待 800ms 或 blur 触发 onChange 落库。
- 事件：onChange/onPressEnter(onEnter 脚本)/onKeyUp/onFocus/onBlur（`:308-311`）。
- 异步：组件值来自 DataSet（setDataSet 监听 DataSetUpdateEvent 与游标切换，`:91-122`）；远程赋值（如放大镜回填）后 DOM value 由 React state 驱动，等 `input` 值变化即可。

### 2.2 FormTextArea / FormTextPassword / FormTextSearch
- FormTextArea：容器 id=`${compMark}-container`，textarea 本体 id=`${compMark}`，wrapper class `osp-form-text-area-comp-wrap`（`ui/FormTextArea.tsx:312,313,335`）。有 maxLength 属性控制、字数统计 class `text-area-show-count-*`（`:304`）。
- FormTextPassword：容器 id=`${compMark}-container`（`:149`）、input id=`${compMark}`（`:174`）。
- FormTextSearch：容器 className=`${compMark}-container`（`:78`）、input id=`${compMark}-input`（`:93`）。
- 均继承 FormBaseDataComp 的 debounce/校验行为（同 §2.1）。

### 2.3 FormNumberInput 数字框
- DOM：antd `<InputNumber className='osp-number-input'>`（`ui/FormNumberInput.tsx:353`），无稳定 id → 用 `.osp-number-input` + 位置定位。
- 精度：`precision={decimalNumber}`（`:384`）；大数模式 `stringMode`（`:381`，值为字符串）。min/max/step 来自 props（`:382-384`）。
- 赋值：`setValue`/输入后 changeFun；fmtValue 是格式化显示值，真实值在组件 `getValue()`（脚本侧）。

### 2.4 FormDateField 日期
- DOM：外层 className=`osp-react-designer-pc-formDataField`（`ui/FormDateField.tsx:487`）；antd DatePicker，`popupClassName='PopupCalendar'`（日期面板稳定类，`:516`），`picker` 支持 date/week/month/quarter（dateTime 映射为 date，`:518`）。
- 格式：`format=this.getFormat(picker)`（`:517`）；值可为时间戳或字符串，内部 `convertToDate` 按 YYYYMMDD/YYYYMM/YYYYMMDDHHmm/YYYYMMDDHHmmss 正则补齐（`:417-429`）。showTime 由格式决定（`:519`）。
- 只读展示态：值为 '--' 时渲染 `<span className='no-value-comp'>--</span>`（`:483`）。
- 禁选日期走脚本 disabledDate（`:391-394`）。面板渲染在 PopupCalendar 容器中，Playwright 点选 `.PopupCalendar .ant-picker-cell[title=...]`。

### 2.5 FormTimePicker / FormMonthComboBox / FormDateRangeField
- FormTimePicker：容器 id=`${compMark}-container`（`ui/FormTimePicker.tsx:162`），picker id=`${compMark}-timer`（`:186`），class `osp-react-designer-pc-formTimePicker`（`:164`）。
- FormMonthComboBox：容器 id=`${compMark}-container`（`ui/FormMonthComboBox.tsx:279`）、select id=`${compMark}-select`（`:302`）、class `FormMonthComboBox`（`:326`）；多选下拉面板 class `osp-multi-select-dropdown-menu`，确认按钮 `osp-multi-select-confirm`（`:198-204`）。
- FormDateRangeField：1063 行（`wc -l`），细节未逐段核对（未确认其内部结构），推测同为 antd RangePicker 封装——用前需再看。

### 3.2 远程字典/下拉帮助 HelpComboBox（type 'HelpComboBox'，设计器名「下拉帮助」）

## 6. 表格（AGGrid / FormTable）

- 就绪等待：`onGridReady`（`:1380`）；自动化等 `.pan-grid` 内 `.osp-row` 出现或 ag-grid `api` 事件（如能拿到实例）。
- 弹层：列头菜单 `.osp-popup .osp-menu`（`:1257,1299`）。

## 8. 按钮 / 弹窗 / 提示

## 12. 自动化最难的点

1. **无 id 组件占表单大半**：文本/数字/日期/单选/简单标签全无稳定 id，label 与控件又无 htmlFor 关联——稳定定位依赖「表单 JSON 的控件 key + 布局结构」重建选择器，或退化为 class+文本+位置的脆弱组合。这是整个自动化框架的第一风险点。
2. **下拉类随机 uuid**：FormComboBox/HelpComboBox 等 id、弹层类名全随机，且弹层挂 body（不受表单容器限定）——多表单/多弹窗同屏时选项列表归属易错判。
3. **校验提示短命且形态可配**：MessageBox 3s 消失、message/alert/window 三形态由环境配置切换（reactEnv.MessageBox），测试环境若配置不同，选择器直接失效；必填 tooltip 挂在根容器而非控件旁，需全局扫描。
4. **AGGrid 是二开封装**：PanGrid 类名与行模型（rowSetKey）依赖公司内部包，行 id=data.id 的生成在 DataSet 侧；asyncInsertRow、fullRow 编辑、临时行标记等事务语义复杂，删行/插行断言需理解 DataSet 事件链而非 DOM。
5. **时序陷阱密集**：800ms onChange debounce、GridToolBar 轮询渲染、cascadertree 单次加载缓存、分页条自行翻页（syncPaginationDisplay）、Tab 非首页签控件尺寸延迟——固定 sleep 不可靠，需要针对每种等待点写专用 wait 辅助函数。
6. **一键多义**：按钮点击即触发脚本动作（executeCompScripts），动作内部可能开窗/提交流程/toast，结果形态不唯一；断言必须锚定业务结果（见 03/04 文档）而非 UI 副作用。
