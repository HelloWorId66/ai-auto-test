# 查资料

你自己去查，不要让用户安装或配置任何东西。地址这类信息由团队提供，通过环境变量给出，不写进工作区的入库文件。

## 资料来源，按可信程度

| 来源 | 用来查什么 |
|---|---|
| 用户给的需求、设计、禅道用例 | 业务目的、规则、异常。有就用，没有也能做 |
| 表单定义（`knowledge/forms/<表单ID>.json`） | 页面上有哪些字段、标签、必填、下拉、表格、按钮 |
| 测试库的配置元数据 | 菜单路径、真实提示文案、下拉选项、数据库列的中文名 |
| 团队知识库（代码和文档） | 后端的业务规则、联动、校验、码值常量、落库逻辑 |
| 真实页面 | 实际的交互和结果。和文档不一致时以它为准 |
| 用户 | 以上都查不清时，用业务话问 |

## 表单定义

```
ifc forms import <表单ID> [<表单ID>...] --from <产品表单定义目录> --product-version 6.2.7
ifc forms list
```

表单定义从产品代码里导入，存进工作区 `knowledge/forms/`，随工作区入库。运行时只读这里，不依赖产品代码。产品代码目录在哪，问用户或团队。

## 测试库的配置元数据（只读）

需要环境变量 `IFCAT_DB_MCP_URL`（测试库查询服务的地址）。

```
ifc tool db_mcp entries <功能号|菜单名|表单ID>      菜单入口和完整菜单路径
ifc tool db_mcp messages <表单ID|功能号|文字>       系统真实的提示文案（写核心异常的预期用）
ifc tool db_mcp columns <业务表名>                  每一列的中文含义（写数据库检查前先看）
ifc tool db_mcp mask <掩码key>                      下拉选项
```

这个工具只放行只读查询。**如果你是通过自己的 MCP 连接直接访问这个服务，注意它带写入类工具，绝对不要调用 `execute` 开头的工具。**

它读的是配置元数据，读不到业务表里的数据（如存款申请记录）。业务数据走环境配置里的只读数据库账号，见 `数据库检查.md`。

## 团队知识库

查业务代码、流程、公共方法、业务文档。优先用你自己环境里已经配置的知识库 MCP。没有的话，设置环境变量 `IFCAT_KB_MCP_URL` 后用：

```
ifc tool kb_query <工具名> '<JSON 参数>'
```

知识库里没有表单定义文件，表单定义只能用上面的 `ifc forms import`。

## 单据模型骨架

```
ifc tool discover_bill --root <产品代码根目录> <流程编号> [<流程编号>...]
ifc tool discover_bill --root <产品代码根目录> --list [--module DP]
```

从业务代码里提取流程的单据头表、主键列、状态列，只读代码，不连数据库。结果表要读代码补充。用法见 `数据库检查.md`。

## 在真实页面上探查

用 `ifc run <场景> --draft` 跑到某一步，看截图和报告；或者写一个只有"打开、填写、检查显示"的草稿场景来观察页面。探查会在测试环境里留下单据，属于测试数据。**不要在生产环境做。**
