# 数据库检查

页面上看到"办结"不等于数据真的落对了。重要的业务结果（单据状态、明细记录、下游指令）要到数据库里核对。**数据库只读**，引擎只允许单条查询语句。

## 前提

1. **环境配置里有只读账号**：工作区 `config/local/<环境>.yaml` 的 `db:` 一节（`kind`、`dsn`、`username`，口令写 `password` 或用 `password_env`）。引擎自带 Oracle；其他数据库在 `extensions/` 里接入，见 `排查与扩展.md`。
2. **单据模型已登记**：工作区 `bills/*.bills.yaml`，并在 `workspace.yaml` 的 `bills` 里列出。它告诉引擎一个流程的单据存在哪张表、用哪一列找、状态是哪一列、结果在哪些表。

## 单据模型怎么写

```yaml
bills:
  流程编号:                      # 场景里的 flow 填这个
    name: 业务名称
    head_table: 单据头表
    key_col: 单据编号所在的列     # 页面上记下来的编号就是按这一列找
    status_col: 状态列
    where: {F_DJLX: "30020052"}  # 可选：单据头表被多种单据共用时，用固定条件限定本流程
    states: {别名: "值"}          # 可选：业务自定义的状态值，来自代码常量
    results:                     # 可选：办结后写入的业务结果表
      结果名:                    # 场景里的 table 填这个
        table: 结果表
        link: {结果表的列: 单据头的列}   # 两张表靠什么关联
        note: 依据和说明
```

- 骨架用 `ifc tool discover_bill --root <产品代码根目录> <流程编号>` 从代码里提取（单据头表、主键列、状态列）。结果表它不猜，要读代码里审批完成后的处理逻辑来补。
- 通用状态别名：`draft` 制单、`in_flow` 审批中、`approved` 审批完成、`voided` 作废。**前提是该流程没有改写平台的默认行为**；有的流程不用这一套，要另找完成标志，写进 `states`。

## 三个检查动作

```yaml
# 单据状态
- {id: d1, as: checker, do: expect_db_status, 说明: 办结后单据状态应为已办结,
   args: {flow: 流程编号, key: "${captured.bill_no}", state: approved}}     # state: not:approved 表示"不是已办结"

# 单据头或结果表里的记录：有没有、字段值对不对
- {id: d2, as: checker, do: expect_db_record, 说明: 存款明细按申请金额生成,
   args: {flow: 流程编号, key: "${captured.bill_no}", table: detail,       # table: head 表示查单据头本身
          expect: {F_JE: "1000", F_ZT: "1"},                               # 列名: 期望值
          wait: 60}}                                                       # 可选：后台异步生成的记录最多等多少秒

# 记录不应存在
- {id: d3, as: checker, do: expect_db_record, 说明: 被拦截的单据不应生成转账指令,
   args: {flow: 流程编号, key: "${captured.bill_no}", table: transfer_order, absent: true}}
```

`expect_db_result`（flow, result, where）按结果表的关联列直接查有没有记录，用得少；一般用 `expect_db_record` 就够了。

办结后单据编号变了，或者页面上拿不到要用的编号时，用 `capture_db` 从单据头里取出来再用：

```yaml
- {id: m9, as: checker, do: capture_db, 说明: 从数据库取出变更单据的编号,
   args: {flow: 流程编号, key: "${captured.bill_no}", column: F_DJBH, name: change_no}}
```

## 两条规矩

**1. 预期值要推出来，不能抄回来。** 检查值必须由输入数据或业务规则算出（如利息 = 本金 × 利率 × 天数 ÷ 360）。先查库看到一个值，再把它写成预期，这种检查永远通过，没有意义。

**2. 列和码值的含义要确认，不能按列名猜。** 按这个顺序：

1. `ifc tool db_mcp columns <表名>`，看平台元数据里的中文列名。元数据可能不全。
2. 码值（如某个状态列的 1、3 各代表什么）元数据里没有，到知识库查后端代码里的常量和判断。
3. 仍不确定，用只读查询拿真实数据对照页面。
4. 还不行，用业务话问用户，并写进 `unconfirmed`。

确认过的列名和码值写进场景的 `labels`（如 `F_JE: 存款金额`、`"F_ZT=1": 有效`），审核页和报告里业务人员看到的就是业务名称。
