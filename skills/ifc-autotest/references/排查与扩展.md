# 排查 blocked，以及引擎缺东西时怎么办

## 排查顺序

1. **看报告**：批次报告里该场景的错误文字和截图。出错时会自动留一张名为"出错"的页面截图。
2. **页面空白或 502**：本机代理或环境问题。引擎的浏览器默认直连；先 `ifc doctor --login` 确认环境可访问、账号可登录。
3. **找不到字段**：核对表单定义（`knowledge/forms/<表单ID>.json`）里的标签，和场景里写的是否一字不差。同名字段用 `occurrence` 或 `within` 区分。
4. **找不到菜单**：核对 `config/local/<环境>.yaml` 里的菜单路径，用 `ifc tool db_mcp entries <表单ID或菜单名>` 重新取。
5. **填了值无效，或被联动清空**：见 `识别页面.md` 第 7 节。
6. **提示"没有标定记录"或"版本不符"**：`ifc calibrate`，探针怎么写见下文"标定怎么写探针"。
7. **提示没有适配器、没有这个动作**：引擎缺东西，见下文。
8. **页面上系统自己报错或一直卡住**：这不是自动化的问题，按疑似产品问题如实上报，附截图。
9. **预期的拦截、提示没有出现**：这是测试发现。最多再试一次确认不是偶发，然后记进 `unconfirmed` 并告诉用户。不要为了找到"在哪个环节拦截"换着法子反复试，每试一次环境里就多一张单据。

要自己写小脚本看页面之前，先试 `ifc view <表单ID>`。确实要写的，放在工作区 `tmp/` 目录（不入库），用完删掉；不要去读引擎源码找内部做法，引擎对外的用法以本技能的文档和 `ifcat.ext` 为准。

**改了已审核的场景之后，审核会失效。** 调试期间用 `--draft` 运行；修好后重新 `ifc render`，请用户再确认一次，然后才能正式运行。如果改的只是环境配置、单据模型或扩展，没有动场景文件，审核不受影响。

## 标定怎么写探针

标定是让引擎在真实页面上把每种控件"填一次、读回来"确认好用。第一次到一个环境、换了产品版本或技能版本后要做。探针写在 `probes/<环境>.calibration.yaml`，并在 `workspace.yaml` 的 `probes` 里登记。标定不保存单据。

- **只给场景用到的控件类型写探针**，每种一条就够。场景用到哪些类型，`ifc validate` 和运行前的提示会告诉你。
- **产品版本先定好再标定**。标定记录按 `config/local/<环境>.yaml` 里的 `product_version` 存，改了版本号就要重新标定。版本号取登录后页面标题栏里的（如"测试V6.2.7-SNAPSHOT"写 `6.2.7-SNAPSHOT`），不要取登录页上的。
- **系统自动生成、不能填的字段**（单据编号、授信编号这类），探针写 `read_only: true`，只验证能读：`{type: FormTextInput, form: 表单ID, label: 授信编号, read_only: true}`。
- **表格里系统已带出的行**，探针加 `existing: true`，不点新增。
- **读回来的格式和填的不一样时**（金额带千分位、利率补零），用 `expect` 写读回的样子：`value: "HKD 1000", expect: "HKD 1,000.00"`。
- **探针按页面联动的先后顺序写**：先填会影响其他字段的（如申请人、类型），再填被影响的。
- 下拉、弹层类的 `value` 必须是这个环境里真实存在的选项。
- 某种类型标定失败：先看失败说明里定位到的是不是目标字段。定位错了多半是标签或表单写错；定位对了但填不进去，说明引擎自带的做法在这个页面上不适用，在 `extensions/` 里补一个控件或动作，并用 `ifc tool propose` 报给维护者。

## 引擎缺东西：在工作区补，不要卡住

做具体功能的人不改引擎。缺一种控件、一个动作，就在工作区 `extensions/` 目录里加一个 `.py` 文件，**只从 `ifcat.ext` 导入**。补完直接在场景里用，把当次工作做完。把它归纳进引擎是维护者定期做的事，不是你的事。

选择器必须来自真实页面的观察，不要猜。

### 缺一个动作（如作废、加签、上传附件）

```python
from ifcat.ext import action, StepResult, BlockedError


@action("void_bill", required=["bill"], text="作废单据", checkpoint=False)
def void_bill(ctx, bill, **_):
    row = ctx.page.locator(".某个来自真实页面的选择器", has_text=bill)
    if row.count() != 1:
        raise BlockedError(f"列表里找到 {row.count()} 条 {bill}，期望 1 条")
    row.get_by_text("作废", exact=True).click()
    shots = ctx.screenshot("作废")
    return StepResult.passed("已作废", shots)
```

- `@action(名字, required=必填参数, text=业务说法, checkpoint=是否算检查点)`。名字不能和自带动作相同。
- 函数签名是 `(ctx, 参数..., **_)`，**必须返回** `StepResult.passed(说明, 证据)`、`StepResult.failed(...)` 或 `StepResult.blocked(...)`。
- 只有"检查点比对不一致"才返回 `failed`。没能做完（找不到、超时）抛 `BlockedError` 或返回 `blocked`。
- `ctx` 里可以用的东西：

| 名字 | 是什么 |
|---|---|
| `ctx.page` | 当前页面（Playwright 的 Page） |
| `ctx.prim` | 引擎自带的操作，可以直接复用，如 `ctx.prim.fill(表单ID, {标签: 值})` |
| `ctx.captured` | 运行中记下的值，可读可写 |
| `ctx.form(表单ID)` | 表单定义 |
| `ctx.db` | 只读数据库连接，没配置时是 None |
| `ctx.ui` | 界面文字配置（按钮名称等） |
| `ctx.screenshot(名称)` | 留一张截图，返回值放进 `StepResult` 的证据里 |

场景里的用法和自带动作一样：

```yaml
- {id: s8, as: maker, do: void_bill, 说明: 经办作废这张单据, args: {bill: "${captured.bill_no}"}}
```

### 缺一种控件

```python
from ifcat.ext import Adapter


class SwitchAdapter(Adapter):
    type_name = "FormSwitch"          # 等于表单定义里这个组件的 type

    def set(self, page, root, value):  # root 是这个字段所在的容器
        ...

    def get(self, page, root):
        ...
```

表格里引擎不带的编辑器码同理，`type_name` 写 `GridCell:<编辑器码>`，如 `GridCell:30`。

新控件要先标定才能用：在标定探针文件里给它加一条探针，再 `ifc calibrate`。

### 缺一种数据库（Oracle 以外）

```python
from ifcat.ext import register_dialect


def connect(cfg):                      # cfg 有 dsn、username、password
    import 某驱动
    return 某驱动.connect(...)


register_dialect("类型名", connect, readonly_begin="开启只读事务的语句")
```

环境配置里 `db.kind` 写这个类型名。只读检查照样生效。

### 约束和后续

- 扩展只能新增，不能覆盖引擎自带的同名控件、动作、数据库。
- 试过但最后没被任何场景用到的扩展，删掉，不要留在 `extensions/` 里。
- 扩展文件加载失败，命令行会明确提示是哪个文件、什么错。
- 用了扩展的场景结果照常有效，报告里会标明"用到工作区扩展"。
- 维护者定期用 `ifc harvest` 汇总各工作区的扩展，决定哪些并入引擎。觉得某个扩展很通用，可以用 `ifc tool propose <扩展文件> "为什么需要、在哪个真实页面验证过"` 主动提案。
