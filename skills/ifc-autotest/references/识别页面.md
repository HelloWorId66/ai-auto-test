# 识别页面：页面由什么组成、怎么认、怎么操作

讲的是产品界面平台（PanUI React）的共同规律，所有模块一样，长期不变。不按单据逐个列字段：某张单据有哪些字段，永远以 `ifc forms import` 取到的表单定义和 `ifc view --options` 看到的真实页面为准。文中的例子来自企业定存和银行授信，只是例子。

## 1. 一张单据页面由什么组成

从上到下：**菜单进入 → 工具栏（保存、提交、编辑……）→ 若干分区（基本信息、结算信息、到期处理、审批流程……）→ 分区里的字段 → 表格（分录）**。操作过程中会出现**弹窗和提示**。提交以后单据进入**流程**，在首页的"我的待办""我的已办""已完成"里流转。

## 2. 组件大类

| 大类 | 业务上是什么 | 怎么填、怎么读 | 引擎现在 |
|---|---|---|---|
| 基础输入 | 文本、多行文本、数字、日期 | 直接输入 | 已支持 |
| 下拉 | 静态下拉：选项来自固定字典；下拉帮助：选项来自业务数据，会随别的字段变化 | 点开选一项 | 已支持 |
| IFC 业务组件 | 单位（申请单位、借款人）、开户机构、账号、国家地区、币种、金额（币种 + 金额）、利率 | 各有固定的弹层或输入方式；金额写成"币种 金额" | 已支持这 7 种 |
| 选择类 | 复选、单选、开关、页签、日期范围 | — | 未自带 |
| 表格（分录） | 一张单据下的多行明细，如品种明细、还款计划 | 新增一行，按列的编辑方式填 | 见第 3 节 |
| 选择原对象的弹窗 | 变更、终止、支取这类功能，一打开就弹出"选择……"让你挑要处理的对象 | 搜索、选中、确定 | 已支持（`pick_record`、`expect_not_listed`） |
| 工具栏动作 | 保存、提交、编辑、同意、退回、取回、作废、加签、上传附件 | 按动作类型认，不按按钮文字猜 | 前 6 种已支持，后 3 种未自带 |
| 提示 | 确认框、业务提醒（"返回 / 继续处理"）、拦截提示、几秒就消失的小提示 | 确认框和业务提醒要选择；小提示只当辅助证据 | 已支持 |
| 查询页 | 条件区 + 结果表格 | 条件区和单据一样填；结果表格页面上读不到文字，导出 Excel 后读 | 已支持 |
| 流程 | 我的待办、我的已办、已完成 | 在列表里找到单据行，行内同意、退回、取回 | 已支持 |

表里写"未自带"的，遇到时按第 9 节处理。

## 3. 怎么认页面上的东西

1. **先找表单**：`ifc tool db_mcp entries <功能号|菜单名|表单ID>`。同一个功能可能有多个入口（核心系统一个、网银一个），没有特别说明时按核心系统（home）的为准。输出里的完整中文菜单路径写进工作区 `config/local/<环境>.yaml` 的 `env_params.forms.<表单ID>.menu`。
2. **以表单定义为准**：`knowledge/forms/<表单ID>.json`，没有就 `ifc forms import <表单ID> --from-env`（见 `查资料.md`）。字段的标签（`showLabelText`）、组件类型（`type`）、必填（`enableNotNullCheck`）、可编辑（`edit`）、对应的数据库列（`dataSetColID`）、下拉选项（`maskConfigKey`，用 `ifc tool db_mcp mask <key>` 取全部选项）、分区（`FormContentPanel` 的标题）、表格的列和编辑器码（`editorType`）、工具栏按钮，都从这里读，不凭页面印象猜。
3. **以真实页面为准**：表单定义和设计文档未必是这个环境上的样子（字段可能被隐藏、禁用、带默认值）。`ifc view <表单ID> --options` 打开新建页，列出每个字段是否显示、必填、能不能填、默认值，表格的列，可用按钮，下拉里的真实选项，并留整页截图。只看不动，不会在环境里留下单据。说"页面上没有某个字段"之前先用它确认。
4. **按类型认，不按文字认**：组件按类型决定操作方式，按钮按动作类型决定是什么动作。
5. **同一个标签可能有好几个**：按条件只显示其中一个（例如两个"起始日期"）。这类"选了 A 就出现 B"本身就是可以检查的业务规则，用 `expect_visible`。例（企业定存）：选"通知存款"后出现"提前通知天数"，到期日期、存款天数、应计利息、到期指示都不显示。
6. **字段的业务含义**：看标签，再用 `ifc tool db_mcp columns <表名>` 查数据库列的中文名。

具体的组件类型和操作方式：

| 组件 type | 怎么填 | 注意 |
|---|---|---|
| FormTextInput / FormTextArea / FormNumberInput | 直接输入 | 只读字段只能读（系统生成的编号用 `capture_field` 读） |
| FormDateField | 输入日期文本 | 格式取自控件 |
| FormComboBox | 点开下拉选一项 | 选项来自掩码 |
| HelpComboBox | 点开弹层选择 | 选项会随其他字段联动 |
| AmountComp | 币种 + 金额，如 `HKD 1000` | 已有值时要全选后逐键输入，引擎已处理 |
| InterestRateInput | 输入，失焦后自动补零 | 读值要在失焦之后 |
| PaymentUnit / PaymentAccount / AccountOpenOrgan / CountryArea / Currency | 业务弹层选择 | 引擎自带 |
| 表格单元格 | 按列的编辑器码：1 文本、3 数值、5 日期、6 和 21 下拉、7 字典帮助 | 30（自定义表单帮助）引擎不带 |

## 4. 工具栏按钮 → 动作

按**动作类型**识别：

- `GeneralActionSave` 保存、`GeneralActionSubmit` 提交、`GeneralAction1` 新建
- `FormEditAction` 编辑
- `FlowSubmitAction` 同意、`FlowRollbackAction` 退回、`FlowRetakeAction` 取回、`FlowEndAction` 作废、`FlowAssignAction` 加签

页面上按钮的 CSS 类是 `<表单ID>-<工具栏key>-<动作key>-show-form`（当前可用）或 `-hidden-form`（当前不可用），可以用它判断单据在当前状态下能做什么。

## 5. 流程怎么走

- **提交**：点"提交" → 确认框里点"提交"。系统可能接着弹业务提醒（如余额不足，带"返回""继续处理"），用 `submit_with_warning` 检查并选择。
- **审批**：首页"我的待办"里找到单据行，行内点"同意" → 确认框点"同意"。一张单可能连续有多个节点，同一个审核人逐个处理。
- **被拦截**：节点校验失败时提示"执行服务失败！……"，单据仍在待办。用 `approve_blocked`。
- **退回**：行内点"退回" → 确认框点"退回"（默认退回至制单）。单据回到制单人待办，节点是"制单"，沿用原单据编号。
- **取回**：提交人在首页"我的已办"里找到单据行，行内点"取回" → 确认框点"取回"，提示"取回成功"。单据回到提交人待办，节点是"制单"。下一节点已处理过的，行内没有"取回"。
- **退回或取回后再提交**：`open_todo`（点流程名称打开单据）→ `edit` → 改需要改的 → `save` → `submit`。打开后要先点"编辑"、保存过，工具栏才有"提交"。
- **办结**：单据出现在首页"已完成"里，且不在待办。
- 首页几个页签的列表同时存在于页面里，只有当前页签的行看得见。引擎只认看得见的行。

## 6. 特殊页面

- **打开即弹出"选择…"窗口**（变更、终止、支取类功能）：窗口里是另一张表单，带搜索框、勾选或点行、"确定""取消"。用 `pick_record` 和 `expect_not_listed`。
- **多选币种**：点开后是多选，必须点弹层里的"确定"才关闭；选中后框里只显示第一项，其余折叠成"+N"。
- **表格里的字典帮助列（编辑器码 7）**：点单元格进入编辑，单元格里是下拉，弹出"编号 名称"表格，点名称所在的行。
- **查询页**：条件区是普通控件，按页面上的条件名称填。结果表格在页面上读不到文字，引擎点"导出"得到 Excel 后读取。
- **菜单**：三栏结构（左边一级、中间模块、右边"分组标题 + 功能"）。分组标题不可点，`ifc tool db_mcp entries` 给出的完整路径可以直接填。

## 7. 平台的共同规律（引擎已处理，写用例和扩展时要知道）

- **联动字段要等**：改了金额、期限这类字段后，利息、天数由服务端重算。`expect_field` 会自动多等几秒。
- **表单刚打开时默认值是慢慢带出来的**：没加载完就保存会失败。`open` 已等待。
- **点"编辑"后会重新加载数据**：先出空表单再回填，回填完成前填的值会被冲掉。`edit` 会等加载完成。
- **重选同一个币种会清空表单**：编辑已保存的单据时重选币种，会清掉周期、利率并重置金额。引擎的处理是币种相同就不重选。
- **小提示只显示几秒，而且可以被配置关闭**：只能当辅助证据。
- **同名菜单被别的菜单项遮挡**：引擎会选真正点得到的那个；菜单展开有动画，会重试。
- **本机系统代理会让内网地址返回 502**：引擎的浏览器默认直连，不走系统代理。

## 8. 结果从哪里证明

按可靠程度：数据库里的状态和结果（单据状态、结果台账、余额和变动记录）> 查询页 > 待办和已完成 > 页面字段 > 小提示。重要的检查点至少用前两种之一。具体怎么查见 `数据库检查.md`。

## 9. 缺了怎么办

- 引擎遇到不认识的组件或动作，会**停下来说明缺什么**，不会乱填。
- 做功能的人不改引擎，在工作区 `extensions/` 里补，写法见 `排查与扩展.md`。补的时候只依据真实页面上观察到的东西。
- 补完当次就能用；是否并入引擎，由维护者定期用 `ifc harvest` 汇总决定。

## 10. 尚未验证，或不在范围（不要当事实用）

- 复选、开关、单选、页签、日期范围这几类组件，引擎没有自带的操作方式。
- 表格的编辑器码 30（自定义表单帮助）。
- 流程动作里的作废、加签、终止。
- Windows 上的完整运行。
- 老式（GWT）页面不在范围，遇到时告诉用户。
