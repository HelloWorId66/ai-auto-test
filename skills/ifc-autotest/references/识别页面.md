# 识别页面：页面上有什么、怎么操作、怎么检查

不管哪个业务模块，拿到一个功能后都用同一套办法。下面的内容来自真实表单定义和测试环境的实际观察；没验证过的单列在最后一节。文中的例子来自企业定存和银行授信，只是例子，方法对所有模块相同。

## 1. 先找表单，再读表单定义

1. **功能 → 表单 ID**：`ifc tool db_mcp entries <功能号|菜单名|表单ID>`。同一个功能可能有多个入口（例如核心系统一个、网银一个），先确认测哪个；没有特别说明时按核心系统（home）的为准。
2. **菜单路径**：上一步的输出里有完整的中文菜单路径，写进工作区 `config/local/<环境>.yaml` 的 `env_params.forms.<表单ID>.menu`。
3. **表单定义**：`knowledge/forms/<表单ID>.json`。没有就用 `ifc forms import <表单ID> --from-env` 从被测环境读取（见 `查资料.md`）。从里面读出：
   - 字段：`showLabelText`（标签）、`dataSetColID`（对应的数据库列）、`type`（组件类型）、`enableNotNullCheck`（必填）、`edit`（可编辑）、下拉的 `maskConfigKey`（用 `ifc tool db_mcp mask <key>` 取全部选项）。
   - 分区：`FormContentPanel` 的标题（基本信息、到期处理、审批流程……）。
   - 表格：网格 key、列表头、列的编辑器码（`editorType`）。
   - 工具栏：按钮标签和动作类型（见第 3 节）。
4. **看真实页面**：`ifc view <表单ID>`。它登录后打开这张表单的新建页，列出每个字段当前是否显示、必填、能不能填、默认值，表格的列，工具栏上哪些按钮可用，并留一张整页截图。加 `--options` 还会把每个下拉、弹层选择字段点开，列出里面的真实选项（只看不选；表格里的下拉不列）。只看不动，不填写、不保存，环境里不会多出单据。表单定义和设计文档说的未必是这个环境上的样子（字段可能被隐藏、禁用、带默认值），**以这里看到的为准**；说"页面上没有某个字段"之前，先用它确认。需要先配好菜单路径（第 2 步）。

## 2. 字段类型 → 操作方式

| 组件 type | 怎么填 | 注意 |
|---|---|---|
| FormTextInput / FormTextArea / FormNumberInput | 直接输入 | 只读的字段只能读不能填（系统生成的编号用 `capture_field` 读） |
| FormDateField | 输入日期文本 | 格式取自控件 |
| FormComboBox | 点开下拉选一项 | 选项来自掩码 |
| HelpComboBox | 点开弹层选择 | 选项会随其他字段联动 |
| AmountComp | 币种 + 金额，如 `HKD 1000` | 见第 5 节 |
| InterestRateInput | 输入，失焦后自动补零 | 读值要在失焦之后 |
| PaymentUnit / PaymentAccount / AccountOpenOrgan / CountryArea / Currency | 业务弹层选择 | 引擎自带 |
| 表格单元格 | 按列的编辑器码：1 文本、3 数值、5 日期、6 和 21 下拉、7 字典帮助 | 30（自定义表单帮助）引擎不带 |

引擎不认识的组件类型或编辑器码，运行时会**停下并说明缺什么**，不会乱填。这时在工作区 `extensions/` 里补，见 `排查与扩展.md`。

## 3. 工具栏按钮 → 动作

按钮按**动作类型**识别，不靠文字猜：

- `GeneralActionSave` 保存、`GeneralActionSubmit` 提交、`GeneralAction1` 新建
- `FormEditAction` 编辑
- `FlowSubmitAction` 同意、`FlowRollbackAction` 退回、`FlowRetakeAction` 取回、`FlowEndAction` 作废、`FlowAssignAction` 加签

页面上按钮的 CSS 类是 `<表单ID>-<工具栏key>-<动作key>-show-form`（当前可用）或 `-hidden-form`（当前不可用）。可以用它判断单据在当前状态下能做什么。

引擎目前自带的流程动作是：保存、提交、编辑、同意、退回、取回。作废、加签还没有自带动作，需要时在 `extensions/` 里补。

## 4. 按条件显示的字段

同一个标签在表单里可能出现多次，同一时刻只有一个可见（例如两个"起始日期"）。用 `expect_visible` 检查"选了某个类型之后，哪些字段该出现、哪些该消失"。

例（企业定存实测）：选"通知存款"后出现"提前通知天数"，到期日期、存款天数、应计利息、到期指示都不显示。

## 5. 已知的坑（均已实测，引擎已处理；写用例和扩展时要知道）

- **联动字段要等**：改了金额、周期之后，利息、天数由服务端重算。`expect_field` 会自动多等几秒。
- **币种重选会清空表单**：编辑已保存的单据时重选同一个币种，会清掉周期、利率并重置金额。引擎的处理是币种相同就不重选。
- **金额框已有值时直接填无效**：要点进去全选后逐键输入。引擎已处理。
- **点"编辑"后会重新加载数据**：先出空表单再回填，回填完成前填的值会被冲掉。`edit` 会等加载完成。
- **表单刚打开时默认值是异步加载的**：没加载完就保存会失败。`open` 已等待。
- **同名菜单被别的菜单项遮挡**：引擎会选真正点得到的那个；菜单展开有动画，会重试。
- **提示（toast）只显示几秒，而且可以被配置关闭**：只能当辅助证据。真正的检查点用页面字段、待办、已完成列表、数据库。
- **本机系统代理会让内网地址返回 502**：引擎的浏览器默认直连，不走系统代理。

## 6. 流程怎么走

- **提交**：点"提交" → 确认框里点"提交"。系统可能接着弹业务提醒（如余额不足，带"返回""继续处理"），用 `submit_with_warning` 检查并选择。
- **审批**：首页"我的待办"里找到单据行，行内点"同意" → 确认框点"同意"。一张单可能连续有多个节点，同一个审核人逐个处理。
- **被拦截**：节点校验失败时提示"执行服务失败！……"，单据仍在待办。用 `approve_blocked`。
- **退回**：行内点"退回" → 确认框点"退回"（默认退回至制单）。制单人的待办里该单据的节点变成"制单"，点流程名称打开单据，工具栏有"提交""编辑"。退回重提沿用原单据编号。
- **取回**：提交人在首页"我的已办"里找到单据行，行内点"取回" → 确认框点"取回"，提示"取回成功"。单据回到提交人待办，节点是"制单"，单据状态回到制单。下一节点已处理过的，行内没有"取回"。
- **办结**：单据出现在首页"已完成"里，且不在待办。

## 7. 特殊页面

- **打开即弹出"选择…"窗口**（变更、终止类功能）：窗口里是另一张表单，带搜索框、勾选或点行、"确定""取消"。用 `pick_record` 和 `expect_not_listed`。
- **多选币种**：点开后是多选，必须点弹层里的"确定"才关闭；选中后框里只显示第一项，其余折叠成"+N"。引擎两种都支持。
- **表格里的字典帮助列（编辑器码 7）**：点单元格进入编辑，单元格里是下拉，弹出"编号 名称"表格，点名称所在的行。
- **查询页**：条件区是普通控件，按页面上的条件名称填。结果表格在页面上读不到文字，引擎点"导出"得到 Excel 后读取。
- **菜单**：三栏结构（左边一级、中间模块、右边"分组标题 + 功能"）。分组标题不可点，`ifc tool db_mcp entries` 给出的完整路径可以直接填，引擎会处理。

## 8. 把材料变成用例：思考顺序

1. 这个功能的**业务目的**是什么？谁用（角色）？
2. 有几种业务分支（类型、选项）？每个分支是不是生产里天天会走的？是，就写一个主流程场景。
3. 有哪些**核心异常**（被业务规则拦截的、被退回的）？证据来自需求里的异常说明，和 `ifc tool db_mcp messages` 查到的真实提示文案。
4. 每个场景的**业务检查点**：计算结果（利息、天数）、条件显示、拦截提示、流程办结、数据库里的结果。
5. 用 `ifc view --options` 对照真实页面，把以上内容写成 `用例设计.yaml`，`ifc design` 生成页面，请用户在页面上确认。**到这里停下，等用户确认。**
6. 确认后才写场景文件、标定、`--draft` 试跑；试跑发现的差异写进 `unconfirmed`，再生成审核页等用户说"通过"。

## 9. 尚未验证（不要当事实用）

- 复选、开关、单选、页签、日期范围这几类组件，引擎没有自带的操作方式。
- 表格的编辑器码 30（自定义表单帮助）。
- 流程动作里的作废、加签、终止。
- 老式（GWT）页面。
- Windows 上的完整运行。
